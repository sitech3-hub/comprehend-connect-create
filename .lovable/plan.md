# 개선 제안 (우선순위 순)

현재 코드를 살펴본 결과, 다음과 같은 개선 포인트를 제안드립니다. 원하시는 항목만 골라서 진행하시면 됩니다.

---

## 🔒 보안 / 정확성 (높은 우선순위)

### 1. 교사 화이트리스트 클라이언트 노출 제거
`src/hooks/useAuth.tsx`의 `TEACHER_EMAILS` 배열이 클라이언트 번들에 그대로 노출됩니다. 이메일 자체는 민감도가 낮지만, **권한 판단을 클라이언트 상수에 의존**하는 구조 자체가 위험합니다.
- 개선: `user_roles` 테이블 + `has_role()` RPC만으로 교사 판정 → 화이트리스트는 DB(혹은 서버 전용 모듈)로 이전.
- 효과: 권한 변경 시 재배포 불필요, 우회 위험 감소.

### 2. `submissions.user_email` / `user_name` 신뢰 문제
현재 `PartView`에서 클라이언트가 `user_email`을 직접 upsert 합니다. RLS가 본인 행만 허용해도 **본인이 본인 이메일을 위조**해 저장할 수 있어요.
- 개선: `auth.uid()`에서 트리거로 자동 채우거나, 컬럼을 제거하고 교사 대시보드에서 join으로 조회.

### 3. 자동 저장(autosave) 부재
지금은 수동 "저장하기"만 있어서 학생이 깜빡하면 데이터 유실 위험.
- 개선: debounce 3~5초 자동 저장 + 페이지 이탈(`beforeunload`) 시 경고.

## 🧩 코드 구조 / 유지보수

### 4. Part ID 타입 중복 (`1 | 2 | 3 | 4`)
여러 파일에서 하드코딩된 union이 반복됩니다(`parts.$partId.tsx`, `PartView.tsx`, `useProgress.tsx` 등). 파트 추가 시마다 수정 필요.
- 개선: `lessonData.ts`에서 `PartId = (typeof PARTS)[number]["id"]` 추출해 재사용.

### 5. 교사 대시보드 데이터 페칭 한계
`supabase.from("submissions").select("*")` — 학생이 많아지면 1000행 한도/성능 이슈. 또한 한 번 fetch 후 갱신 없음.
- 개선: 페이지네이션 또는 Realtime 구독, 그리고 교사용 수동 새로고침 버튼.

### 6. `useProgress` / `useCriteria` 중복 호출
여러 컴포넌트가 마운트될 때마다 동일 쿼리를 반복합니다.
- 개선: TanStack Query 도입 (캐싱·invalidate·재시도 일원화). 이미 의존성에 있을 가능성 높음.

### 7. 인라인 SVG (Google 로고) 분리
`index.tsx` 내 큰 SVG가 가독성을 해침 → `components/icons/GoogleIcon.tsx`로 추출.

## 🎨 UX / 접근성

### 8. 키보드/스크린리더 접근성
`QuizItem`의 선택지가 `<button>`이라 OK지만, **선택 그룹**임을 알리는 `role="radiogroup"` / `aria-checked`가 없음. Reflection 글자수도 `aria-live`로 안내하면 좋습니다.

### 9. 정답 즉시 노출 문제 (교육적 고려)
선택 즉시 ✓/💡 힌트가 표시되어, 학생이 **"맞을 때까지 클릭"** 할 수 있습니다.
- 개선 옵션: (a) 제출 전까지 결과 숨김, (b) 1회 시도 후 잠금, (c) 교사 설정으로 모드 전환.

### 10. 모바일 가독성
`PartNav` 카드 4개가 모바일에서 세로로 길어집니다(889px 뷰포트에선 OK, 그 이하에서 스크롤 부담). 가로 스크롤 탭으로 전환 고려.

### 11. 인쇄 친화 레이아웃 (워크스페이스 규칙 반영)
학습용 활동지 특성상 인쇄 수요가 있을 수 있음 → `@media print` 스타일 추가, sticky 저장바·헤더 숨김.

## 📊 운영 / 모니터링

### 12. 교사 접근 거부 로그 영속화
`logTeacherAccessDenied`가 콘솔 로그만 남깁니다. 재시작/재배포 시 사라짐.
- 개선: `access_logs` 테이블 또는 Lovable Analytics로 기록.

### 13. 완료 기준 변경 이력 부재
`completion_criteria` 변경이 학생 완료율에 즉시 영향을 주는데, 변경 이력/변경자가 기록되지 않음.
